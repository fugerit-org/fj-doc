=== Headless Linux InternalError / InvocationTargetException when resizing Excel sheet

On headless Linux environments (such as Docker containers or servers without a graphical interface), an error may occur when invoking:

[source,text]
----
at org.fugerit.java.doc.mod.poi.PoiUtils.resizeSheet()
----

For instance during `BasicPoiTypeHandler.handle()`.

==== Root Cause

Apache POI's column auto-sizing feature (`autoSizeColumn()`) calculates font metrics and character widths through Java AWT (`TextLayout` and `Font`). On minimal Linux installations lacking `fontconfig` and font packages, Java fails to initialize the font subsystem, throwing an `InternalError` caused by a `NullPointerException` in `FontConfiguration.getVersion()`.

==== Solutions

* **Install `fontconfig` and fonts on your operating system (Recommended)**:
+
[source,sh]
----
# Alpine Linux (apk)
apk add fontconfig ttf-dejavu

# Debian / Ubuntu (apt)
apt-get install -y fontconfig fonts-dejavu-core

# RHEL / CentOS / Fedora (dnf/yum)
dnf install -y fontconfig dejavu-sans-fonts
----

* **Configure Venus Fugerit Doc to ignore auto-resize errors**:
+
You can set `excel-fail-on-autoresize-error` to `false` in the document metadata (see xref:#doc-faq-clean-resize-xls[FAQ]):
+
[source,xml]
----
<info name="excel-try-autoresize">true</info>
<info name="excel-fail-on-autoresize-error">false</info>
----

* **Configure Apache POI to ignore missing font systems**:
+
Starting with Apache POI 5.2.0+, you can instruct POI to bypass the font subsystem:
+
[source,sh]
----
-Dorg.apache.poi.ss.ignoreMissingFontSystem=true
----
+
or in Java:
+
[source,java]
----
System.setProperty("org.apache.poi.ss.ignoreMissingFontSystem", "true");
----
